# Ручной код и результаты генерации API

| Расположение | Владелец | Можно редактировать вручную? |
| --- | --- | --- |
| `__generated__/` целиком | Генератор | Нет |
| `<группа>/index.ts`, `index.server.ts` | Разработчик: публичные входы | Да |
| `<группа>/*-api.ts` | Разработчик: правила кэша | Да |
| `base-api.ts`, `server-request-config.ts`, `server-transport.ts` | Разработчик: транспорт | Да |
| `scripts/api/`, `api.config.ts` в корне проекта | Разработчик: инструменты | Да |

`npm run api:generate` полностью восстанавливает или обновляет `__generated__`.
`npm run api:clean` удаляет только `__generated__`; ручные файлы сохраняются.
После очистки повторите генерацию перед проверкой типов, тестами или сборкой.

Публичные импорты остаются `@/shared/api/account` для hooks и типов и
`@/shared/api/account/index.server` для серверной фабрики и типов SDK.
Другие группы используют тот же шаблон. Импорты из __generated__ нужны только
инфраструктурным фасадам, настройкам API и тестам.

Клиентские входы групп также экспортируют Zod-схемы, сгенерированные из OpenAPI
плагином `zod` (например, `zLoginRequest` из `@/shared/api/auth`). Схемы
генерируются отдельно от server-only SDK. Правила и сообщения, относящиеся к
форме, добавляются поверх схемы в коде экрана.

Два генератора и дублирование некоторых TypeScript-типов сохранены намеренно:
этот рефакторинг меняет размещение файлов и их жизненный цикл.

## Типизированное сопоставление тегов

`__generated__/schema-tags.ts` содержит актуальный список тегов операций и тип
OpenApiTag. `api.config.ts` проверяет им значения apiModules и полноту
покрытия. Имена модулей слева выбираются разработчиком; теги справа берутся из схемы.

`npm run api:generate` сначала обновляет этот снимок, затем выводит полный отчёт
о сопоставлениях и пропусках. При ошибке сопоставления snapshot обновляется для IDE,
но прежние API-файлы сохраняются. Исправьте apiModules и повторите генерацию.
При ошибке загрузки/разбора схемы даже прежний снимок остаётся неизменным.

Снимок удаляется командой api:clean вместе со всем __generated__. Следующая
генерация восстанавливает его до проверки типов конфигурации, без зависимости
от старого generated-кода. После успеха выводятся количества операций по группам,
RTK endpoints, серверных методов и записанных файлов.

## Чаты и события AI

`@/shared/api/chats` экспортирует generated HTTP hooks, `useChatHistoryInfiniteQuery`,
`useChatMessagesInfiniteQuery`, `useChatFilesInfiniteQuery` и
`useWatchChatRunQuery({ chatId, runId, attempt? })`.
HTTP остаётся в существующем `baseApi`. Ручные настройки обеспечивают multipart
загрузку и инвалидацию чатов, сообщений, файлов и runs только при успехе mutation.
Infinite queries делегируют HTTP generated endpoints и хранят страницы в RTK Query.

`watchChatRun` владеет WebSocket, повторной выдачей билетов и курсором `seq`.
Подписки одного run разделяют соединение. После последней отписки или logout
соединение и таймеры закрываются. Разрыв соединения не отменяет серверную задачу.
События `harness.step` обновляют шаг по `step_id`; `answer.completed` содержит
готовый ответ, а не текстовые токены. После terminal AI-события endpoint проверяет
Django run раз в 2 секунды до terminal статуса: worker сохраняет сообщение позже
AI, поэтому только затем обновляется история. Источник контракта —
`../ai/docs/websocket-events.md` от корня frontend.

На production WS использует текущий origin и возвращённый Django путь `/ai/...`.
При необходимости задайте `NEXT_PUBLIC_AI_WS_ORIGIN` перед запуском/сборкой
(например, `http://localhost` для локального Nginx). Обычный `next dev` на 3000
проксирует HTTP `/api`, но сам не обслуживает AI WebSocket: нужен настроенный
Nginx или отдельный WS origin. Origin страницы должен входить в `AI_ALLOWED_ORIGINS`.
Сервисные ключи AI клиенту не требуются.

Страница удерживает подписки выполняющихся runs при переключении чатов.
При полной перезагрузке известные run IDs теряются: API чата пока не возвращает
активный run. Сохранённая переписка доступна через HTTP.

## Сравнения baseline / harness

`@/shared/api/comparisons` экспортирует generated hooks
`useComparisonsListQuery`, `useComparisonsCreateMutation`,
`useComparisonsRetrieveQuery` и типы. Серверный вход —
`@/shared/api/comparisons/index.server`.
Ручной `comparisons-api.ts` преобразует создание в multipart: `questions`,
`answers`, повторяющиеся `documents` и optional `model_id`. Успешное создание
инвалидирует историю; переход detail в terminal статус обновляет историю.
HTTP по-прежнему обслуживает один `baseApi` с session credentials.

Страница выбирает одну модель и сравнивает baseline / harness. Сохранённый промт
профиля фиксируется backend при создании запуска. Статус detail опрашивается
каждые 2 секунды до completed/failed; история — каждые 5 секунд, пока её текущая
страница содержит активные запуски. Опрос пропускается в неактивном окне.
Сравнения не имеют публичных WS-билетов, отмены или удаления в текущем контракте.

OpenAPI описывает before/after результата как произвольные объекты. Локальный
адаптер страницы проверяет фактическую структуру оценок перед построением диаграмм
и таблицы. Она содержит оценки и причины по вопросам, а не тексты ответов моделей.
Проценты выполнения и имена сохранённых файлов API не возвращает.
Черновик с выбранными File остаётся локальным состоянием страницы при просмотре
истории и очищается после успешного создания; после перезагрузки он не сохраняется.
