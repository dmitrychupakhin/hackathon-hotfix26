# Проверка PostgreSQL, файлов и обновлённого harness

## Результат разработки

Готовы общая PostgreSQL-схема `ai` (применяет backend/deployment), каталог файлов по ID, read-only source volume, частный кеш оригинал/TXT/metadata, токенные фрагменты с перекрытием, компактный контекст чата, предварительные факты, независимый критик, режимы plain/harness и типизированный OpenAPI. Backend-код и глобальный Compose не изменялись.

Рабочие defaults: модель `openai/gpt-6-luna`, API `https://apimira.com/v1`, из APIMIRA_MODEL/APIMIRA_BASE_URL. Backend может опустить поля или выбрать разрешённые значения. Короткий список шести примеров Model ID добавлен в README и Swagger.

## Автоматические проверки

- **227 тестов прошли** в полном прогоне, включая opt-in настоящую PostgreSQL.
- Проверена отдельная ограниченная роль AI с GRANT из инструкции, включая техническое право UPDATE(updated_at) для FOR SHARE.
- Проверены single-worker advisory lock, owner scope, транзакции, восстановление незавершённых runs, атомарная публикация пакета/импорта/события.
- Проверены кеш по SHA/версии/парсеру, безопасные пути, symlink rejection, конкурентный кеш, частичное извлечение и новый файл версии.
- Повторный импорт той же версии сохраняет document ID и package revision.
- Проверены маленькое окно, адаптивное уменьшение, ограничение попыток и сохранение принятых ответов.
- Проверены plain/profile/defaults/base URL allowlist, общий формат результата и запрос уточнения.
- Ruff check/format и git diff --check — без ошибок.
- OpenAPI содержит **32 HTTP пути** и совпадает с действующей схемой. RunResult → Answer → Span/Check, RunMetrics/APIError доступны для генерации клиента.

Тесты используют поддельные модели; они не доказывают фактическую точность LLM. Есть предупреждение Starlette о будущем переходе TestClient с httpx на httpx2, ошибок тестов нет.

## Независимые ревью

Пять субагентов работали над кешем, фрагментами/фактами, контекстом/режимами и двумя ревью. Исправлены замечания: размер фрагмента после уменьшения окна, HTTP422 для некорректного имени, стабильность повторного импорта, cleanup старта, атомарность состояния импорта и событий, порядок сохранения истории перед terminal run, типизация Swagger и права PostgreSQL. Финальные ревью не выявили блокирующих замечаний.

Известное ограничение сохранено в README: если сами промпты/схемы/собранные доказательства не помещаются, возможен честный отказ; рекурсивная перегруппировка любого набора вопросов/фактов не обещается.

## Интеграция

Для локальной проверки используется отдельный PostgreSQL из docker-compose.local.yml. Production/shared БД создаёт backend; нужно применить SQL, настроить DSN/права/volume, регистрировать ai.files и передавать авторизацию/профиль/IDs по контракту. Реальный backend этим изменением не подключён и не изменён.

Прежний SQLite-файл сохранён, автоматическая миграция старых запусков не выполнялась. Очистка старых артефактов/TTL и распределённый worker не реализованы; один AI процесс контролирует очередь.
