# Файлы и TXT-кеш AI

AI читает оригиналы из общей папки `AI_SOURCE_ROOT` и создаёт собственные копии
в `AI_FILE_CACHE_ROOT`. Папку оригиналов нужно подключать к контейнеру AI **read-only**,
папку кеша — read-write. Оригиналы backend не изменяются. URL и произвольный путь
в HTTP-запросе не принимаются: клиент передаёт ID, а путь разрешается по данным
в общей PostgreSQL после проверки владельца.

## Обязанности backend и развёртывания

Backend/deployment создаёт PostgreSQL и применяет [001_ai_schema.sql](../sql/001_ai_schema.sql)
в **той же базе**, что используется backend. AI не создаёт базу и не применяет DDL
при старте. Схема `ai` отделена от таблиц Django; код backend этим изменением
не обновляется.

Backend регистрирует в `ai.files` текущую версию источника:

| Поле | Контракт |
|---|---|
| `owner` | Идентификатор пользователя/аккаунта; должен совпадать с доверенным `X-User-ID` |
| `id` | Непрозрачный ID: `[A-Za-z0-9][A-Za-z0-9_-]*`, максимум 128 символов |
| `version` | Непустая версия, максимум 128 символов; менять при изменении содержимого |
| `updated_at` | Timestamp с часовым поясом; нормализуется в UTC |
| `filename` | Исходное имя с расширением, без пути, максимум 200 символов |
| `relative_path` | Нормализованный POSIX-путь относительно `AI_SOURCE_ROOT`; без `..`, symlink и абсолютных путей |
| `sha256` | SHA-256 оригинальных байтов, 64 hex-символа |
| `media_type` | MIME исходника, например `application/pdf` |

Backend сначала полностью записывает новую **неизменяемую** версию файла,
затем одной транзакцией обновляет `ai.files`. При обновлении рекомендуется новый
`relative_path`: не перезаписывать файл, который другой процесс уже читает.
Значение времени загрузки не определяет приоритет условий закупки.

## Структура диска

```text
AI_FILE_CACHE_ROOT/
  sha256(owner)/
    sha256(file_id)/
      sha256(version + source_sha256 + filename + media_type)/
        parser_fingerprint/
          original.pdf
          extracted.txt
          metadata.json
```

Имена директорий хешированы, чтобы ID/версии не превращались в локальные пути.
`artifact_key` — относительный путь к последней директории; это идентификатор
артефакта, а не HTTP URL. Backend не должен открывать по нему произвольные пути.
Фактическое имя локального оригинала — `original` с безопасным расширением,
а исходное имя сохраняется в метаданных и `ParsedFile.name`.

`metadata.json` содержит время генерации `generated_at`, исходные метаданные,
хеш TXT, отпечаток парсера, предупреждения, признак `partial` и координаты
извлечённого текста (страница/лист/слайд при наличии). TXT всегда UTF-8;
смещения координат заданы в символах итогового текста, не в байтах PDF.

## Когда извлечение повторяется

1. Для ID найдена новая версия/новый SHA, имя или MIME.
2. Отсутствует полный артефакт/TXT.
3. Изменился отпечаток парсера: исходники извлекателя, версия формата кеша,
   установленные версии `pypdf`/`defusedxml`, лимиты, OCR и язык OCR.

При каждом `prepare()` AI проверяет владельца и **фактический SHA оригинала**,
включая попадания в кеш. Изменённый источник с устаревшей записью в БД вызывает
`source_changed` (409), а старый TXT не выдаётся как актуальный.
`updated_at` сохраняется для аудита; одно сравнение дат не доказывает актуальность.
Если дата обновилась, а версия/байты/параметры прежние, повторное извлечение не нужно.

Для прямой HTTP-загрузки `prepare_bytes()` сохраняет те же три файла. SHA байтов
используется как версия. Такая загрузка не регистрирует источник в `ai.files`;
без переданного внутреннего `file_id` создаётся новый UUID.

## Конкурентность и ошибки

- POSIX `flock` на ключ артефакта исключает двойной запуск извлечения между
  экземплярами FileCache/процессами, использующими одну локальную папку.
- Подготовка выполняется во временной директории `.extract-*`, затем директория
  атомарно переименовывается в итоговую. Читатель не получает половину TXT.
- Отсутствующий TXT/metadata вызывает повторное извлечение; неполная старая
  директория перемещается в `.incomplete-*` для разбирательства.
- Повреждённый TXT (несовпадающий SHA), некорректные метаданные или подмена
  владельца дают `file_cache_corrupt` (503). Автоматически доверять таким данным нельзя.
- Все компоненты пути источника открываются через `dir_fd` с `O_NOFOLLOW`;
  symlink и нестандартные объекты вроде FIFO не читаются.
- Источник больше настроенного лимита отклоняется с `file_too_large` (413),
  отсутствующий — `source_file_not_found` (404), недоступный —
  `source_file_unavailable` (503). Ошибки не раскрывают абсолютные пути.
- Парсер сохраняет `partial`/`warnings`; частичное извлечение не становится
  основанием для уверенного «нет в документах».
- Кеш не имеет автоматического TTL/сборщика мусора. Старые версии и
  `.incomplete-*` хранятся до отдельного обслуживания; удалять версии,
  используемые сохранёнными запусками, без политики хранения нельзя.

Каталог кеша должен принадлежать только пользователю процесса AI (директории
артефактов создаются с правами 0700). `flock`/atomic rename рассчитаны на локальную
POSIX-файловую систему; поведение NFS/S3 не входит в контракт этого кеша.

## Внутренний интерфейс и проверка

```python
from app.infrastructure.files.cache_models import SourceFile
from app.services.file_cache import FileCache

cache = FileCache(source_root, cache_root, ingestor, max_bytes=10 * 1024 * 1024)
artifact = await cache.prepare(SourceFile.model_validate(database_row), owner_id)
# artifact.parsed: ParsedFile (text, locations, warnings, partial, hashes)
# artifact.cache_hit: bool
# artifact.artifact_key: относительный ключ
# artifact.text_path: внутренний Path; не возвращать абсолютный путь клиенту
```

Офлайн-тесты: `pytest tests/test_file_cache.py -q`. Покрыты попадания в кеш,
изменение источника и версий, конкурентная публикация, partial/страницы,
инвалидация по настройкам, неполные артефакты, повреждения, symlink, ограничения
размера и настоящий изолированный TXT-парсер. Сетевые модели в них не вызываются.
