# Сравнение по заданию ОНСОФТ

## Неизменённые входы и одинаковые закупки

В `/comparison-inputs/parse` передаются owner-scoped ID исходных `questions.csv`, `answers_public.json`, `document_file_ids`. CSV имеет колонки `id;package;question`; JSON — исходный список эталонов. Разбор выполняется кодом без LLM: сохраняются ID, тексты, package, expected, kind, type и дополнительные поля. Несовпадение ID/закупок и неоднозначность отклоняются, ожидаемые ответы не достраиваются. Файлы вопросов/эталонов не включаются в источники генератора. Подготовка с `Idempotency-Key` повторно возвращает те же package IDs для того же пользователя и набора ID файлов; другой payload с тем же ключом даёт 409.

Документы: один ZIP с `packages/P01/...txt`, …, `packages/P06/...txt` (также MD) либо плоские поддерживаемые файлы **одной** закупки. ZIP может содержать исходный questions.csv, который должен совпасть с отдельным CSV; answers_public.json и check.py из ZIP никогда не загружаются в источники и не выполняются. Неподдерживаемые документы внутри packages явно отклоняются. Для PDF/DOCX и прочих поддерживаемых парсером оригиналов используйте плоские файлы одной закупки: молча пропускать часть закупки нельзя.

## Было и стало

Оба режима получают одинаковые вопросы и версии исходников одной и той же модели/провайдера. Группировка `options.question_grouping=per_package`: каждый пакет отдельно, все его вопросы вместе. Для шести закупок baseline делает шесть логических генераций. Он запрашивает стандартный JSON/CSV-контракт, включая quote/file, но не проверяет цитаты и не исправляет ответы. Цитаты заполняет модель в первом ответе; человек или код не дописывают доказательства после генерации.

Harness получает те же источники и вопросы, технические инструкции и профильные `additional_instructions`, как Django-чат. Проверяет цитаты, числа, расчёты, смысл, изменения и противоречия, допускает ограниченное исправление и неизвестный ответ. Изменение промпта — часть улучшения, а точные шаблоны и профиль фиксируются для воспроизведения. `system_prompt` остаётся отдельным продвинутым override; сравнение Django его не использует.

Метрика — исходный judge организатора: `(correct-errors)/questions*100`. «Не знаю» даёт 0. Сравнение отклоняет разные модели, провайдеры, вопросы, источники, эталоны или группировку. Плохой результат не скрывается. Равные оценки означают нулевое измеренное улучшение.

## Отказы, бюджет и артефакты

Окно baseline не расширяется за счёт скрытого RAG или дополнительных проходов. Если он не помещается, обрывается по output limit либо провайдер не отвечает, score недоступен (`null`), а не 0. Успешный результат второго режима сохраняется, delta при несопоставимой паре отсутствует. Упавшие AI runs нельзя отправлять в `/evaluate` как обычный accuracy score. Доступные частичные ответы и техническая причина сохраняются для аудита.

Лимиты общие на run, не на вопрос: 48 известных HTTP-попыток к модели, 8 раундов на закупку, 1 исправление. Обычный запрос чата ограничен 600 с; полное сравнение по умолчанию запрашивает 1200 с на режим (включая очередь), worker ожидает оба режима совместно до 1260 с после подготовки, затем отменяет незавершённые. `AI_COMPARISON_TIMEOUT_SECONDS` задаёт бюджет сравнения в backend, `AI_RUN_TIMEOUT_SECONDS` — верхний потолок AI (1200 по умолчанию); эффективный timeout — минимум запроса и потолка. Согласуйте эти значения в окружении. Импорт ограничен отдельно. При 429 ограниченный транспортный повтор разрешён до получения ответа, учитывается в `transport_attempts` и общем бюджете; `model_calls` считает логические вызовы. Сетевой таймаут автоматически не повторяется. Данных о списании может не быть: при отсутствующем тарифе или неполном usage стоимость остаётся неизвестной.

Результат содержит ответы/цитаты/checks, отклонённые кандидаты, разбор по типам вопросов, входные/выходные/кешированные токены, время, вызовы и уменьшения контекста. Для completed оценок сохраняются точные `prompt_snapshots`, хеши и effective_options. Owner-scoped JSON-отчёт Django содержит также зафиксированные `profile_instructions`; ключи провайдера/сервиса в отчёт не включаются.

Django: `GET /api/comparisons/{id}/answers.csv?mode=baseline|harness`, `GET /api/comparisons/{id}/report.json`. CSV имеет исходные ID и разделитель `;`; сохранённый run JSON содержит точные оригинальные evidence/координаты, переносы строк нормализуются только для совместимости экспортированного CSV с check.py. CSV двух режимов можно независимо проверить оригинальным `python check.py answers.csv --gold answers_public.json --packages packages`.

Перед защитой: прогон всех 71 вопросов без ручных исправлений, два CSV, общий индекс и разбивка по типам, 2–3 реальных отклонённых/исправленных ответа и расход ресурсов. Отдельно проверяется большой источник с поздней поправкой и маленьким настроенным окном; такой стресс-тест не заменяет основной замер качества на исходном наборе.

## Как повторить проверку организаторов в интерфейсе

1. Откройте `/comparisons`, создайте новый анализ и выберите одну модель. Сравниваются два режима этой же модели, а не две разные модели.
2. В поле вопросов загрузите исходный `questions.csv` (71 строка), в поле эталонов — исходный `answers_public.json`. Эталоны используются только оценщиком после генерации.
3. В документы загрузите ZIP с исходной структурой `packages/P01/...` … `packages/P06/...`, без перемешивания файлов разных закупок в один плоский каталог. Можно использовать учебный ZIP организатора; эталоны и check.py из него не становятся источниками модели.
4. Запустите анализ и дождитесь завершения обоих режимов. «Было»: шесть прямых запросов, по одному на закупку, без критика, инструментов и исправлений. «Стало»: та же группировка и источники, с проверками харнесса. Планировщик свободного чата `chat_plan` здесь не вызывается.
5. Посмотрите индекс доверия, верные ответы, обманы, «не знаю», разбивку по типам и конкретные отклонённые кандидаты. Технический отказ с оценкой «недоступно» не считается нулевым качеством и не доказывает улучшение.
6. Скачайте `answers-baseline.csv`, `answers-harness.csv` и JSON-отчёт. Положите CSV рядом с оригинальными `check.py`, `answers_public.json`, `packages/` и выполните:

```bash
python check.py answers-baseline.csv --out result-baseline.csv
python check.py answers-harness.csv --out result-harness.csv
```

Итоги check.py должны совпасть с интерфейсом. Не редактируйте ответы, цитаты или статусы вручную. Для защиты сохраните оба CSV и отчёт с моделью, точными промптами, временем и расходом вызовов; выберите 2–3 реальных случая ошибки и её проверки. Если в конкретном прогоне ошибок меньше, не создавайте искусственный разбор.

Новый контрольный набор прогоняют замороженной системой без правок под ответы жюри. Если эталоны жюри не выданы, результат нельзя объявлять измеренным индексом доверия: генерируйте `answers.csv` через AI `/runs` по новым вопросам/документам и передайте его организаторам для оценки. Текущая страница `/comparisons` предназначена для размеченного набора и требует файл эталонов.
