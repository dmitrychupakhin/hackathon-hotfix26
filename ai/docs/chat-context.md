# Контекст чата и версии источников

AI сохраняет полную историю в `session.messages`, но не отправляет её целиком модели. Никакие старые сообщения не удаляются. Отдельные поля сессии:

- `context_state`: последний вопрос пользователя, предыдущий содержательный вопрос-тема и ссылки на доказательства последнего запуска;
- `file_bindings`: актуальные файлы закупки — `file_id`, `document_id`, версия, SHA-256 текста, имя и состояние обработки.

Перед каждым запуском привязки файлов заново строятся по текущему пакету документов. Для импортированного файла используются `source_file_id` / `source_version`, для обычного текста — ID документа / SHA-256 текста. Новая версия не меняет уже созданный снимок старого запуска.

В `run.snapshot.chat_context` фиксируются выбранная закупка и её ревизия, краткий предыдущий вопрос, вопрос-тема, полный список привязанных файлов и ссылки на доказательства. В `snapshot.history` хранится единственная запись `kind=chat_context` с JSON этого состояния. Она является ссылочным контекстом, не источником фактов. Реальный текущий вопрос передаётся отдельно.

Ответы ассистента, их числа и цитаты в новое состояние не копируются. Ссылки на доказательства содержат только ID, хеш и координаты; ссылки на предыдущую версию документа исключаются. Каждый новый ответ требует чтения оригинальных источников. Для неоднозначного «а какой у него срок?» модель получает краткие прошлые вопросы и правило запросить уточнение, если связь неясна. Определение темы — эвристика по пользовательским вопросам, а не гарантированное разрешение местоимений.

По умолчанию на текст прошлых вопросов выделяется приблизительно 1000 токенов (консервативная оценка: два символа на токен), максимум 1200 символов на один вопрос. Привязки файлов и координаты — обязательные метаданные; они не отбрасываются ради этого целевого размера. `estimated_tokens`, `metadata_exceeds_dialogue_budget` и `dialogue_text_truncated` явно отражают оценку размера и сокращение текста. Общий лимит входа по-прежнему контролирует harness: если метаданные, системные инструкции и вопрос не помещаются, запуск не должен выдумывать ответ.

Поля сессии создаются лениво на первом запросе. Это совместимо со старыми сессиями без `context_state`: прошлый вопрос извлекается из сохранённых пользовательских сообщений, ответы ассистента игнорируются. PostgreSQL хранит сообщения и состояние через общее хранилище AI; реализация не читает и не изменяет таблицы Django.

Проверки: длинная история с большим ответом, сохранность всех файлов при малом бюджете, обновление версии и исключение устаревших ссылок, неизменность снимка, два последовательных запроса через HTTP с сохранением полной истории.
