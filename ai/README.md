# ОНСОФТ AI: ответы с источниками и проверками

FastAPI-сервис для кейса «ИИ, который не обманывает». Два основных режима: `plain` — прямой ответ модели, `harness` — чтение источников, инструменты, проверки кодом, независимый критик и ограниченное исправление.

**Контракт для backend:** [docs/backend-integration.md](docs/backend-integration.md). **События WebSocket с русскими названиями:** [docs/websocket-events.md](docs/websocket-events.md). Действующая HTTP-схема — `/openapi.json`; снимок в репозитории — [openapi.json](openapi.json).

Чат с документами передаёт сообщение целиком модели для смыслового выделения независимых частей ответа, без парсинга вопросов по строкам. Код проверяет полное сохранение исходного текста и назначает ID; каждая часть получает свои цитаты, расчёт, проверки и статус. Полное сообщение остаётся общим контекстом. Планирование занимает один запрос (до двух при ошибке), входит в общий бюджет и имеет шаг `chat_plan`. Максимум 50 частей; при неверном плане запуск останавливается с `invalid_chat_plan`. Чат без документов и сравнительные прогоны готового `questions.csv` этот шаг не используют. Контракт подробнее в [backend/chats/README.md](../backend/chats/README.md).

При неверном JSON, ID вопроса или ссылке на чужую порцию сканер делает один дополнительный запрос только для ошибочных строк на той же порции оригинала. Успешные строки и порции повторно не запрашиваются. Оба обращения входят в общий бюджет. Если независимая проверка отдельного вопроса после повтора всё ещё некорректна, этот вопрос получает техническое «не знаю»; прошедшие проверку остальные ответы сохраняются. Ошибка доступности или формата проверки не запускает переписывание ответа генератором. Это не отменяет проверки цитат и решения критика.

Независимое чтение и финальный критик повторяют один упавший запрос при `provider_timeout`, `upstream_timeout`, `provider_unreachable` или `service_unavailable` (пауза 1с, те же данные, общий бюджет и дедлайн сохраняются). При повторном отказе провайдера адаптер `/chat-runs` сохраняет фактический ответ и цитаты, если все проверки кодом пройдены: `reason=independent_review_incomplete`, `checks` содержит неуспешный `review_unavailable`. Чат показывает сам ответ; API не утверждает, что ИИ-проверка пройдена. Статус «нет в документах» таким способом не принимается. Универсальные runs и сравнения сохраняют прежнее строгое поведение — неподтверждённый ответ становится «не знаю».

## Общая PostgreSQL и файлы

AI и Django используют **одну PostgreSQL**, но AI работает в отдельной схеме `ai`, не читает таблицы пользователей Django. Backend создаёт базу, применяет [sql/001_ai_schema.sql](sql/001_ai_schema.sql) и выдаёт AI доступ. Приложение AI **не создаёт БД/таблицы при старте**. В SQL нет Django migrations и нет изменений таблиц backend.

- `ai.files` — каталог исходников, который заполняет backend: владелец, ID, версия, имя, относительный путь, SHA-256, дата обновления и MIME.
- `ai.objects` — закупки, диалоги, запуски, импорты и оценки AI в JSONB.
- `ai.events` — сохраняемый журнал шагов и результатов.
- Оригиналы и TXT-копии хранятся на диске. В PostgreSQL также сохраняются тексты в снимках входа и пакетах для воспроизводимости; бинарные оригиналы в БД не помещаются.

Backend монтирует свой каталог исходников в AI как **read-only** `AI_SOURCE_ROOT`. AI создаёт частный кеш `AI_FILE_CACHE_ROOT`: хеш владельца / хеш file_id / версия / версия парсера / `original.ext`, `extracted.txt`, `metadata.json`. TXT создаётся рядом с локальной копией оригинала, а файл backend не изменяется. Пересоздание требуется при отсутствии TXT, изменении SHA/версии исходника или парсера. Сравнения дат недостаточно. Детали: [file-cache.md](docs/file-cache.md).

SQLite сохранена только для быстрых изолированных тестов (`AI_ENV=test` без DSN). Рабочий development/production AI требует PostgreSQL. Автоматического переноса прежней SQLite нет; старые данные/volume не удаляются.

## Запуск

### С общей БД, подготовленной backend

В корневом `.env` или `ai/.env` задайте `AI_DATABASE_URL`, например `postgresql://ai_user:password@postgres-host:5432/shared_database`. Это секрет, не пример реального пароля. Для production задайте `AI_ENV=production` и `AI_SERVICE_KEY` минимум 32 символа.

Выполнить SQL должен владелец БД со стороны backend/deployment:

```bash
psql "$AI_DATABASE_URL" -v ON_ERROR_STOP=1 -f ai/sql/001_ai_schema.sql
```

Если приложение получает ограниченную роль, SQL запускается отдельной deployment-ролью. Пример разделения прав описан в контракте backend.

```bash
cd ai
docker compose --env-file ../.env up --build -d
```

`AI_SOURCE_DIR` — каталог **на хосте**, который Compose монтирует в `/source:ro`; в нём должны находиться пути из `ai.files.relative_path`. По умолчанию `ai/incoming`. Он исключён из Git. Кеш и артефакты сохраняются в volume `ai-data:/data`.

Контейнер должен иметь сетевой доступ к PostgreSQL backend. Корневые Compose, nginx и код backend здесь не меняются. На Linux для опубликованного локального порта БД доступен `host.docker.internal`; для внутренней Docker-сети подключите AI к общей сети в deployment-конфигурации.

### Изолированный локальный стенд

Для разработки предоставлен **необязательный** локальный PostgreSQL. Его создаёт контейнер БД через init SQL, а не приложение AI. Это стенд, а не автоматическое создание production-БД backend:

```bash
cd ai
docker compose --env-file ../.env -f docker-compose.yml -f docker-compose.local.yml up --build -d
```

Локальная БД доступна только на `127.0.0.1:55432`, использует явно тестовые credentials из local compose. Backend при необходимости может подключиться к ней той же DSN; его настройки здесь не меняются. Production использует свою подготовленную общую БД.

- Swagger: http://127.0.0.1:8010/docs
- OpenAPI: http://127.0.0.1:8010/openapi.json
- ReDoc: http://127.0.0.1:8010/redoc
- Health: `/health/live`, `/health/ready`

`down` без `-v` сохраняет данные. Провайдерные ключи читаются из существующего `.env`, в образ и репозиторий не попадают.

### Без Docker

Linux/Python 3.11+, `uv sync --frozen`, затем:

```bash
uv run uvicorn app.main:app --host 127.0.0.1 --port 8010 --workers 1
```

Перед запуском должны существовать БД/схема и каталог `AI_SOURCE_ROOT`. Для OCR нужны Poppler и Tesseract rus+eng; в Docker они установлены. OCR по умолчанию выключен.

## Авторизация

Каждый backend-запрос к `/api/v1` передаёт:

```http
X-AI-Service-Key: <общий секрет backend → AI>
X-User-ID: <ID пользователя, проверенный backend>
```

AI проверяет сервисный ключ и изолирует ресурсы по пользователю; чужие ресурсы — 404. Пользовательские JWT и профиль принадлежат Django. `X-User-ID` доверяется после проверки сервисного ключа. В локальном режиме без ключа используется один владелец `local`; переданный произвольный user ID не создаёт изоляцию.

Сервисный ключ не передаётся браузеру. Backend получает WS-билет на конкретный run/import. `/docs`, OpenAPI и health открыты, содержимое документов через них не выдаётся.

## Контракт режимов и профильный промпт

Backend передаёт одинаковые вопросы, `package_id`, модель и при необходимости `system_prompt`; переключатель — `mode`:

```json
{
  "mode": "harness",
  "model": "openai/gpt-6-luna",
  "system_prompt": "Инструкции из профиля пользователя",
  "questions": [{"id": "P01-05", "package_id": "UUID", "text": "Какой размер обеспечения?"}]
}
```

| mode | Поведение |
| --- | --- |
| `plain` | Один прямой запрос с профильным/встроенным простым system prompt и контрактом JSON; без tools, факт-проверок, критика, repair и chunk loops |
| `harness` | Источники, tools, проверка цитат/чисел, независимый критик, ограниченное исправление, неизвестное вместо неподтверждённого |
| `baseline` | Точка «было»: один user message на закупку с минимальным контрактом, без system, tools, критика и исправлений |
| `raw` | Legacy-диагностика: исходные документы/вопросы одним user message без system и формата; отсутствующие статусы не домысливаются |

В чат принимаются `plain`/`harness`; в runs/datasets доступны все четыре. Значение по умолчанию — `harness`. Формат run одинаковый: `id`, `status`, `mode`, `request`, `result.answers`, `metrics`, `error`, хеши промптов и версии источников. Для plain `checks=[]` — это **не подтверждённый ответ**. Если JSON нарушен, run получает `plain_format_invalid`, сырой ответ сохраняется; повторов/проверок в plain нет.

`system_prompt` заменяет инструкции генератора выбранного режима, максимум 32000 символов. Отсутствие/null использует встроенный вариант. В `raw`/`baseline` поле запрещено, чтобы не менять протокол эксперимента. Backend передаёт актуальный профиль при каждом запросе; AI не читает профиль Django напрямую. Старые runs не меняются после редактирования профиля. Критик, сканирование и проверки остаются частью сервиса. Для сравнения plain/harness используйте общие инструкции без обязательного вызова tools, доступных только harness. Подробности: [api-modes.md](docs/api-modes.md).

`Idempotency-Key` поддержан для runs/messages/dataset runs: тот же ключ и тело возвращают прежний run, иное тело (включая prompt/mode) — 409. Импорт файлов по ID использует отдельные job IDs; повторный импорт той же версии — cache hit с сохранением document ID и revision, а не новый фактический источник.

## Модель и API по умолчанию

`model` и `base_url` необязательны во всех трёх маршрутах создания runs/dataset-runs/messages. Если поле отсутствует или `null`, сервер подставляет значения `.env`:

```dotenv
APIMIRA_MODEL=openai/gpt-6-luna
APIMIRA_BASE_URL=https://apimira.com/v1
```

Поэтому минимальный backend-запрос может содержать только mode и вопросы/сообщение. Явный ID модели передаётся настроенному провайдеру без отдельного списка разрешённых моделей в AI. URL должен совпадать с настроенным или входить в `AI_ALLOWED_BASE_URLS`. Сервис отправляет свой `APIMIRA_API_KEY` только на эти адреса; ключ не передаётся в теле backend-запроса. URL с credentials/query/fragment запрещены, HTTPS обязателен кроме локальных тестов. Дополнительный адрес должен быть OpenAI-compatible и подходить к имеющемуся ключу; выбора разных ключей по URL здесь нет.

`GET /info` сообщает `default_model`, `default_base_url`, доступные метаданные моделей провайдера и разрешённые адреса. Список моделей для фронтенда хранится в Django. Swagger показывает фактические серверные defaults. В `run.model`, `run.base_url`, `run.request` и snapshot фиксируются выбранные значения; сравнение разных base_url отклоняется. Для дополнительного провайдера метаданные окна не подменяются каталогом основного — используется консервативный fallback.

Короткий список текстовых моделей из присланного каталога ApiMira (в том срезе отмечены «Работает»):

| Модель | Model ID |
| --- | --- |
| GPT-6 Luna — по умолчанию | `openai/gpt-6-luna` |
| GPT-6 Astra | `openai/gpt-6-astra` |
| GPT-5.4 Mini | `openai/gpt-5.4-mini` |
| Claude Sonnet 4.6 | `anthropic/claude-sonnet-4.6` |
| Gemini 3 Flash | `google/gemini-3-flash-preview` |
| DeepSeek V4 Flash | `deepseek/deepseek-v4-flash` |

Это **шесть примеров**, не гарантия текущей доступности и не результат шести живых прогонов. Список моделей для пользователей задаётся в таблице Django `AIModel`; AI использует переданный Django ID. Основные живые прогоны текущей версии выполнены на Luna. Статус/параметры уточняются в [каталоге ApiMira](https://apimira.com/models).

## Harness, фрагменты и контекст чата

Цикл: оригиналы → предварительные факты и точные цитаты → проверки кодом → независимый критик → исправление либо «не знаю». Инструкции внутри файлов считаются данными.

- Стартовые фрагменты — 2000 **оценочных** токенов, overlap 200. Оценка `символы / 2` является proxy, не точным tokenizer Luna. Границы выбираются по предложениям/строкам; обычные строки таблиц сохраняются, если помещаются. Автоматический повтор заголовков длинных таблиц не гарантируется.
- Если окно уменьшилось, уменьшаются сами фрагменты и перекрытие, а также порции результатов чтения/tools. Оригиналы не обрезаются.
- `auto` передаёт полный пакет, если помещается, иначе обходит бюджетные порции. `retrieval` начинает с индекса и tools, `full` требует целого пакета.
- Для большого входа сканер собирает предварительные факты: поле, значение, единицу, условие, тип связи, источник/цитату. Это не окончательные ответы. Одинаковые повторные находки с одинаковыми исходными координатами объединяются; противоречащие значения сохраняются.
- Критик получает кандидата, журнал находок, покрытие и оригиналы. Если они велики, независимо обходит все порции, включая поздние изменения. Пустой фрагмент не доказывает отсутствие сведений в пакете.
- `result.evidence_audit` содержит аудит каждой закупки/попытки: ledger, покрытие, прочитанные блоки и принятые вопросы. Сырые scan outputs доступны в `raw_outputs` для аудита.
- Чат хранится полностью. В модель идут текущий вопрос и компактное состояние: закупка, предыдущие вопросы пользователя, ID/версии файлов и ссылки на доказательства. Предыдущие ответы ассистента не становятся фактами. Для неоднозначного уточнения harness может вернуть status «не знаю» и `clarification_question`; backend показывает этот вопрос пользователю, а factual answer/evidence остаются пустыми. Привязки файлов сохраняются отдельно от переписки. Детали: [chat-context.md](docs/chat-context.md), [chunking-and-review.md](docs/chunking-and-review.md).

Статусы: `ответ`, `расхождение`, `нет в документах`, `не знаю`. Для отсутствия сведений нужно полное успешное покрытие; partial/OCR/пустой или непрочитанный источник не разрешает уверенное отсутствие. Для конфликта нужны оба значения/доказательства. Явное изменение заменяет только указанный пункт; дата загрузки не назначает приоритет условиям. Семантический критик тоже может ошибаться.

Tools: `list_documents`, `search_documents`, `read_document`, `read_evidence`, `find_amendments`, `calculate`, `submit_answers`. Нет shell, произвольного Python, внешнего поиска или доступа к эталонам.

Официальное сравнение использует неизменённые CSV/JSON и одинаковую группировку `per_package` для обоих режимов: шесть базовых генераций на шесть закупок. Эталоны доступны только оценщику. `additional_instructions` добавляет профиль к техническим правилам harness, как в чате; это отличается от продвинутого полного override через `system_prompt`. Контракт, ZIP и воспроизведение: [comparison-protocol.md](docs/comparison-protocol.md). Большие источники и компактные доказательства: [large-context.md](docs/large-context.md).

HTTP 429 повторяется только как транспортный отказ, с `Retry-After` или ограниченной задержкой; настройка `AI_RATE_LIMIT_RETRIES` по умолчанию 3. Повторы входят в общий `max_calls` и deadline, новые генерации после готового baseline-ответа не выполняются. `model_calls` — логические генерации, `transport_attempts` — HTTP-попытки, включая 429. Сам HTTP-адаптер таймауты и сетевые сбои не повторяет; независимая проверка в harness выполняет один отдельный повтор такого запроса, как описано выше. Этот повтор учитывается отдельным `model_calls` и входит в тот же бюджет. `APIMIRA_ENABLE_THINKING=false` передаётся только при явной настройке оператором для поддерживающей этот параметр модели; по умолчанию параметр отсутствует. Выходной потолок задаёт `AI_LLM_MAX_OUTPUT_TOKENS` (8000 по умолчанию, до 32000), `options.max_output_tokens` может его уменьшить, но не повысить.

## Окно модели, попытки и время

При старте читаются `GET /models`: рабочий лимит — минимум метаданных провайдера и настроенного потолка. По умолчанию потолок 266000; без метаданных fallback не выше 160000. `/info.model_context_budgets` сообщает источник/лимит. Каждый run фиксирует свой бюджет.

При **машинной ошибке** `context_length_exceeded` в harness auto/retrieval новый потолок не больше половины старого окна и половины оценки отклонённого входа. Затем неподтверждённая попытка перестраивается с меньшими порциями. Уже принятые ответы сохраняются. Ограничения не обнуляются. Обычная ошибка цитаты, обрезанный ответ, HTTP 429 и сетевой сбой не запускают уменьшение окна.

Если сами инструкции/схемы/совокупность релевантных фактов не помещаются, возможен честный отказ. Минимальная граница 4096 не обещает, что любая комбинация промпта и tools поместится в такое окно. Рекурсивное дробление большого списка вопросов пока отсутствует.

| --- | ---: |

| Раунды генерации/tools на закупку | 8 |

После перезапуска незавершённые jobs/runs становятся `interrupted`, платные запросы сами не повторяются.

## Проверка качества и воспроизводимость

Учебный ZIP содержит `packages/P01..P06` и `questions.csv`. `answers_public.json` и `check.py` **не загружаются в генерацию**. Эталоны передаются отдельно только в `/evaluate` после terminal run.

```bash
uv run python -m app.cli import /path/to/school21-onsoft-data
uv run python -m app.cli run DATASET_ID --mode baseline --model openai/gpt-6-luna --output output/baseline --references /path/to/answers_public.json
uv run python -m app.cli run DATASET_ID --mode harness --model openai/gpt-6-luna --output output/harness --references /path/to/answers_public.json
uv run python -m app.cli compare BASELINE_EVALUATION_ID HARNESS_EVALUATION_ID
```

CLI работает с уже запущенным API. Plain также доступен через `--mode plain`; пользовательский `system_prompt` передаётся через HTTP API. Сравнение отвергает разные модели, вопросы, версии источников, историю/контекст чата или эталоны. `check.py` сохранён отдельно от harness. Индекс доверия = `(верно − ошибки) / все вопросы × 100`; это не вероятность истинности отдельного ответа.

Цена вычисляется только при полных usage и заданных `AI_INPUT_PRICE_PER_MILLION`, `AI_OUTPUT_PRICE_PER_MILLION`. Если `AI_CACHED_PRICE_PER_MILLION` не задана, для кеша берётся цена обычного входа. Кэш — часть входных токенов; не добавляется второй раз. Без тарифа/полного usage стоимость `null`. Наличие реальных результатов на нескольких вопросах не заменяет полный замер 71 вопроса.
